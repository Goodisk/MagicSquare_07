# MagicSquare_021 — Cursor Rules 설계 및 생성 보고서

작성일: 2026-05-28 (세션 기록) / 최종 갱신: 2026-05-28 (파일 재구성 반영)

---

## 개요

이 보고서는 MagicSquare_021 프로젝트에 적용할 Cursor Rules 파일을 설계·생성하고, 이후 파일 구조를 재구성한 전체 과정을 기록합니다.

---

## 1. 요구 조건 (사용자 정의)

| 항목 | 내용 |
| ------ | ------ |
| 언어 | Python 3.13.13 (현재 PC 설치 버전) |
| 스타일 | PEP8, type hints 필수 |
| 테스트 | pytest + AAA 패턴 |
| 아키텍처 | ECB (boundary / control / entity) |
| 개발 방법론 | Dual-Track TDD |
| 금지 사항 | `print()` 디버깅, 테스트 약화, RED 없는 구현 |

## 2. 방식 선택 — `.cursorrules` vs `.cursor/rules/*.mdc`

### 비교 검토

| 항목 | `.cursorrules` | `.cursor/rules/*.mdc` |
| ------ | --------------- | ---------------------- |
| 파일 수 | 단일 파일 | 복수 파일 분리 |
| 적용 범위 제어 | 불가 | `globs` 또는 `alwaysApply`로 제어 |
| 규칙 집중도 | 낮음 (혼재) | 높음 (관심사 분리) |
| 유지보수 | 어려움 | 용이 |

### 결정

`.cursor/rules/*.mdc` 방식 선택.

**이유:** 이 프로젝트의 규칙은 성격이 세 가지로 명확히 다르다.

- 항상 적용해야 할 프로세스 규칙 (TDD 흐름)
- Python 파일에만 적용할 스타일 규칙
- 테스트 파일에만 적용할 품질 규칙

단일 파일로 혼재시킬 경우 AI가 중요 규칙을 누락할 위험이 있다.

---

## 3. 규칙 파일 구조 (최종)

초기 4개 파일(`01~04.*.mdc`)에 AI 행동 규칙 파일(`05.ai-behavior.mdc`)이 추가되었다가,
이후 전체를 관심사 기준으로 재구성하여 현재 5개 파일 체계로 정착하였다.

### 최종 파일 구조

```text
.cursor/rules/
  magicsquare-project.mdc          — alwaysApply: true
  magicsquare-tdd-testing.mdc      — alwaysApply: true  / globs: tests/**/*.py
  magicsquare-ecb-architecture.mdc — globs: src/**/*.py
  magicsquare-python-code-style.mdc — globs: **/*.py
  magicsquare-forbidden.mdc        — alwaysApply: true
```

### 재구성 원칙

- 파일명을 숫자 접두사 대신 내용을 명시하는 이름으로 변경
- 기존 `01.tdd-process` + `04.test-quality` → `magicsquare-tdd-testing`으로 통합
- 기존 `05.ai-behavior`의 금지 패턴 + 각 파일의 금지 목록 → `magicsquare-forbidden`으로 통합
- 프로젝트 맥락(불변 조건, 브랜치 전략) → `magicsquare-project`으로 분리 신설

## 4. 생성된 파일 상세

### `magicsquare-project.mdc` — alwaysApply: true

**목적:** 프로젝트 전반 맥락. Python 파일을 열지 않은 상태에서도 항상 컨텍스트에 포함된다.

**핵심 내용:**

- 프로젝트 목적 (검증 기준을 구현보다 먼저 세우는 사고 훈련)
- 7개 핵심 불변 조건 (격자 크기, 숫자 집합, 중복 금지, 행/열/대각선 합, 완성의 불가분성)
- Dual-Track 브랜치 전략: `spec` / `red` / `green` / `refactoring` 재사용 구조
- 커밋 메시지 컨벤션: `[RED]`, `[GREEN]`, `[REFACTOR]` 접두사
- 진행 단계 (STEP 1~7)

---

### `magicsquare-tdd-testing.mdc` — alwaysApply: true / globs: tests/**/*.py

**목적:** TDD 프로세스 절대 규칙과 pytest 테스트 품질 기준을 통합한 파일.
기존 `01.tdd-process.mdc`와 `04.test-quality.mdc`를 병합하였다.

**핵심 내용:**

- RED / GREEN / REFACTORING 단계별 규칙과 금지 항목
- AAA 패턴 필수 (`# Arrange`, `# Act`, `# Assert` 주석 명시)
- 테스트 함수명 컨벤션: `test_<대상>_<조건>_<기대결과>`
- 하나의 테스트 = 하나의 동작 검증 원칙
- `conftest.py` fixture 사용 가이드 및 scope 기준
- 최소 80% 라인 커버리지 설정

---

### `magicsquare-ecb-architecture.mdc` — globs: src/**/*.py

**목적:** 프로덕션 코드(`src/`)에만 ECB 레이어 규칙 적용.

**핵심 내용:**

- Entity / Control / Boundary 레이어 디렉토리 매핑
- 의존 방향 강제: `Boundary → Control → Entity` (역방향 import 금지)
- 이 프로젝트의 구체적 함수 매핑 예시 (`validate`, `_check_*`, `parse_*`)
- 레이어별 금지 사항 및 완전한 디렉토리 구조 명세

---

### `magicsquare-python-code-style.mdc` — globs: **/*.py

**목적:** 구현 및 테스트 파일 모두에 적용하는 Python 언어 스타일 규칙.

**핵심 내용:**

- Python 3.13 기준 — `X | Y` 타입 표기, `match/case` 문법 예시
- 모든 함수에 인자 타입 + 반환 타입 type hints 필수
- Google 스타일 docstring (public 함수/클래스 필수)
- Black 포매터 기준 최대 88자, `pyproject.toml` 설정 예시
- PEP8 네이밍 테이블 (snake_case / PascalCase / UPPER_SNAKE_CASE / `_` 접두사)
- 모듈 레벨 `Final` 상수 선언 규칙 (매직 넘버 금지)

---

### `magicsquare-forbidden.mdc` — alwaysApply: true

**목적:** 모든 상황에서 절대 금지되는 패턴과 AI 코드 생성 행동 규칙을 한곳에 통합.
기존 `05.ai-behavior.mdc` 및 각 파일에 분산되어 있던 금지 목록을 통합하였다.

**핵심 내용:**

- 코드 품질 금지 패턴 (`print()`, 하드코딩 상수, bare except, 타입힌트 누락)
- 테스트 약화 패턴 코드 예시 (bool 비교 완화, `pass` 대체, 예외 무시)
- ECB 역방향 의존 금지
- AI 코드 생성 전 사전 확인 항목 (테스트 파일, 브랜치 컨텍스트, ECB 레이어)
- AI 코드 생성 후 위반 감지 시 경고 메시지 테이블
